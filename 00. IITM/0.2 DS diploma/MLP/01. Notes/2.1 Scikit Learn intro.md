# The most important Scikit-learn API design principles 

Scikit-learn has a consistent design, Once you understand a few common methods, you can use many different models without learning an entirely new interface each time

## A. Estimator : `fit()`
An **estimator** is an object that learns something from data.
```python
model.fit(X_train, y_train)
```

- `X_train` contains training features 
- `y_train` contains the correct target values 
- `fit()` learns the model parameters from the training data 

```python 
from sklearn.linear_model import LogisticRegression

model = LogisticRegression()
model.fit(X_train, y_train)
```

The model has now been trained

# B. Predictor : `predict()`
A **predictor** uses what it learned to produce predictions 

```python
y_pred = model.predict(X_test)
```

For a *classifier*, predictions are usually class labels. 
For a *regressor*, predictions are numerical values. 

This returns estimated class probabilities when supported by the estimator. 

# C. Transformer : `transform()`

A **transformer** changes the representation of the input data.

Common examples include : 
- `StandardScaler` - standardizes numerical features 
- `OneHotEncoder` - encodes categorical features 
- `PCA` - projects data on a lower-dimensional space 
- `SimpleImputer` - fills in the missing values 

example, 
```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()

X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled = scaler.transform(X_test)
```

![[Pasted image 20261027161030.png]]

***Critical exam concept***: Fit the scaler on training data only. 
Use that fitted scaler to transform the test data. 
Fitting it on the test data can cause data leakage. 

# D. `score()`

Many estimators have a built-in `score()` method 

```python
model.score(X_test, y_test)
```

This produces a default evaluation score, but its meaning depends on the estimator.
- for **classifiers**, it is **accuracy**
- for many **regressors**, it is **coefficient of determination, $R^2$**
Do not assume, `score()` always means accuracy

# F. Model evaluation API - `sklearn.metrics` 

### Purpose - Determine how well a model's predictions match the true values.

![[Pasted image 20261027161635.png]]

Example, 
```python
from sklearn.metrics import accuracy_score, f1_score

y_pred = model.predict(X_test)

print(accuracy_score(y_test, y_pred))
print(f1_score(y_test, y_pred))
```
Accuracy is not always enough. For an imbalanced dataset, such as fraud detection, a model can achieve high accuracy while missing many fraudulent transactions. 


![[Pasted image 20261027161716.png]] 

Example, 
```python
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score
import numpy as np

y_pred = model.predict(X_test)

mae = mean_absolute_error(y_test, y_pred)
mse = mean_squared_error(y_test, y_pred)
rmse = np.sqrt(mse)
r2 = r2_score(y_test, y_pred)
```

For MAE, MSE and RMSE, **smaller values generally indicate better predictions**. 
For $R^2$, a **higher value is generally better**, though it can be negative. 


#### Clustering Metrics 
Clustering group observations without requiring class labels during training.

Some metrics access the quality of clusters, including:
- silhouette score
- Adjusted Rand index, when reference labels are available. 
- Normalised mutual information, when reference labels are available.

example, 
```python
from sklearn import KMeans
from sklearn.metrics import silhouette_score

model = KMeans(n_clusters=3, random_state = 42)
labels = model.fit_predict(X)

print(silhouette_score(X, labels))
```

Silhouette ranges from [-1 to 1]; Higher values = better-separated clusters 

*Remember* - appropriate metric depends on the ML task and what you want to measure.
